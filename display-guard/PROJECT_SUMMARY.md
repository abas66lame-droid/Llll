# مشروع أنظمة العارضات — الملخص الشامل (للنقل إلى Claude Code)

> شركة إلكترونيات كبيرة في العراق (هواتف جديدة ومستعملة، أجهزة منزلية، حاسبات، ألعاب).
> حوالي 600 عارضة و300 موظف في عدة فروع.
> المشروع فيه نظامان مستقلان، كلاهما ملف HTML واحد بالعربي RTL، بدون أي مكتبة بناء:
>
> 1. **نظام نظافة العارضات** (في المستودع: `display-cleaning/`): يجبر الموظفين على تنظيف الغبار الخفيف ويتحقق من التنظيف بالصور.
> 2. **حارس العارضات** (`display-guard/`) — **وهو النظام النشط حالياً**: كاميرا موبايل أو كاميرا عادية تراقب العارضة، تكشف الشيل أو النقص، تفرّق بين البيع والتنظيف والعرض للزبون والسرقة، وتنبّه.

## 2) نظام نظافة العارضات (النسخة القديمة؛ الحالية `display-cleaning/`)

التفاصيل الكاملة للنسخة الحالية في `display-cleaning/SUMMARY.md`. أهم النقاط:

- **الوظيفة:** لكل عارضة كود من 4 أرقام وملصق QR وفترة تنظيف بالساعات.
  1. الموظف يمسح الكود ويصوّر العارضة قبل التنظيف.
  2. ينظّف (يوجد حد أدنى للثواني).
  3. يصوّر بعد التنظيف.
  4. النظام يحسب «مؤشر الغبار» ويقارن الصورتين.
  - هناك نقاط ولوحة ترتيب مهنية، وتدقيق عشوائي من المشرف، وتقارير.
- **خوارزمية الغبار:**
  1. رمادي، ثم blur 3×3، ثم high-pass (الفرق عن المتوسط المحلي)، ثم عتبة MAD.
  2. connected components: نقاط صغيرة حجمها ≤ 36–40 بكسل وصندوقها ≤ 9–10 بكسل.
  3. `مؤشر = 100·(1−e^(−density·sens/8))`.
  4. فحص أن صورة «بعد» هي نفس العارضة: ارتباط بصمة 24×18.
  5. معايرة: `sens = 0.667/density`.
- **طبقة البيانات:** كل الوصول عبر كائن `Store`.
  - حالياً يستخدم `window.claude.use('db')` (قاعدة Claude Artifacts)، أو `localStorage` (`dh2_data`) احتياطياً.
  - **عند النقل:** استبدل `Store` بـ Firebase Firestore (الأقرب) أو Supabase.
  - المجموعات: `config, zones, staff, sum, act, proof`.
- **الصلاحيات:** حالياً من مالك الـ artifact، أو PIN `1234` في الوضع المحلي. تحتاج مصادقة حقيقية عند النقل.

## 3) حارس العارضات (`display-guard/`) — النظام النشط

### 3.1 الفكرة ببساطة

1. الموظف يثبّت الموبايل على حامل أمام العارضة ويفتح `haris.html`، ثم يضغط «📷 تشغيل الكاميرا».
2. يرسم بإصبعه مستطيلاً أو أكثر على الصورة، وكل مستطيل «عارضة» (zone). الصورة تتجمد أثناء الرسم.
3. كل ثانية (أو كل `poll` ثوانٍ في التشغيل العادي)، النظام يقارن كل عارضة مع «صورتها المرجعية».
4. **شيل** قطعة ← حالة «معلّقة» مع صور: قبل / بعد / قص مقارن / صورة اليد أو الشخص لحظة التفاعل.
   - رجعت القطعة ← «رجعت» (تُغلق تلقائياً).
   - سُجّل بيع ← «مباعة».
   - انتهت المهلة ← «حادثة» + تنبيه (إشعار، صوت، تيليجرام).
5. **إضافة** قطعة جديدة، أو تبديل مكانها ← حدث معلوماتي فقط، والمرجع يتحدّث.

### 3.2 البناء

- `src/page.html` (~800 سطر) يحتوي العلامة `/*__DETECTOR__*/`.
- `build.py` يحقن ما بين `/* DETECTOR_START */` و `/* DETECTOR_END */` من `src/detector.js`، والناتج `haris.html`.
- `detector.js` يُصدّر `DET` في المتصفح، و `module.exports` في Node للاختبارات.
- **المكتبة الخارجية الوحيدة:** MediaPipe tasks-vision 0.10.14 من CDN (jsdelivr للكود و storage.googleapis للنماذج). إذا لم تتحمّل، يعمل النظام بدونها.

### 3.3 تدفق كل إطار (`loop` ثم `ENG.process(c, ppl)`)

```
grabFrame (عرض 960) → DET.frameFromCanvas → build(gray blur, gradient G, ca/cb لون, integral)
→ [اختياري] mpPeople: أشخاص + أيدي (MediaPipe) → ENG.process:
   1) لمس الشاشة خلال 2.5ث        → حالة touch، توقف، settle=2
   1ب) العدسة مغطاة أو مظلمة (DET.health) → حالة blind، لا حكم ولا rebase، تنبيه tamper بعد blindSec
   2) motion(prev,cur) كامل > 0.45 → الكاميرا تتحرك، توقف، settle≥2
   3) settle: قراءتان مستقرتان (gm<0.03) ثم إذا اختلفت عن المرجع (gb>0.04) → rebaseAll + رسالة
   4) estimateShift + gBase=motion(base,cur): إذا gBase>0.22 و(إزاحة≥4بكسل أو gBase>0.6) ومستقر وبلا أشخاص
        → قراءتان ثم realign: مطابقة المرجع القديم بالتحويل الأفيني ومقارنة العارضات (النقص يفتح حالة) ثم rebaseAll
      (ونفس realign بعد الاهتزاز/الحركة في الخطوة 3 بدل rebaseAll المباشر)
   5) لكل عارضة:
       - يد داخلها (مع هامش 4%) أو شخص يغطي >35% → انتظار + لقطة تفاعل (img_p) + عدّ تفاعل
         (الشخص الثابت 3 قراءات بلا حركة لا يمنع الحكم)
       - motion(prev,cur) داخل العارضة: frac>0.01 أو cnt≥3 → «تنتظر: حركة»
       - compareZone(base, cur, z, shift, {fine})
       - changed>0.5 → 3 قراءات تأكيد؛ إذا بلا rem/add → حدث «major» (أو حادثة ليلاً) + rebase
       - شخص أو يد يلامس منطقة التغيّر → تأجيل (ذراع تغطي القطعة ≠ شيل)
       - mergeNear(regions, 0.04) ثم:
           rem: إذا يتداخل >50% مع حدث مفتوح → تجاهل، وإلا newRemoval
           add/chg: إذا يتداخل >35% مع حدث مفتوح → returned، وإلا newInfo('added'|'swap')
       - rebase(z) ← المرجع يتجدد بعد كل قراءة محسومة (هذا سر التكيّف مع تغيّر المنتجات)
   6) «إعادة محاذاة هادئة»: إزاحة بسيطة مستقرة وكل العارضات «ok» بلا مناطق → rebaseAll
```

### 3.4 محرك الكشف `detector.js` (DET)

**تحضير الإطار** (`build`):
- رمادي مع blur.
- تدرج G (قوة الحواف = «التفاصيل/الملمس»).
- قناتا لون `ca=R−G` و `cb=(R+G)/2−B`.
- integral image.

**الإزاحة:**
- `estimateShift`: بحث ±16 بكسل بدقة ¼ للصورة كلها.
- `estimateAffine`: إزاحة + دوران + تقريب للصورة كلها (يُستخدم فقط عند إعادة الضبط بعد حركة الكاميرا).
- `zoneShift`: تحسين ±12 بكسل لكل عارضة. هذا يعالج «تنفّس» التركيز، لأن التقريب يزيح الأطراف أكثر من المركز.

**`compareZone(ref, cur, z, shift, {fine})`:**
- **شبكة خلايا:**
  - عادي: `cs = zw/20` بين 10 و40 بكسل.
  - دقيق: `cs = zw/32` بين 6 و30 بكسل.
- **لكل خلية:** بحث محلي ±`cs/6` حول الإزاحة.
  - التشابه = `0.45·NCC(رمادي) + 0.55·NCC(تدرج)`، ويؤخذ الأفضل.
  - ملمس المرجع `tr`، وملمس الحالي عند الأفضل `tb`، و `tmin/tmax` عبر الإزاحات.
- **تعويض التعريض وتوازن الأبيض** (مشكلة الآيفون):
  - `gain` = وسيط نسبة السطوع، و `dA/dB` = وسيط فرق اللون.
  - تُقدّر **فقط من الخلايا ذات التشابه ≥ 0.6**، حتى لا يؤثر الشيل نفسه على التقدير.
  - ثم: `md = |cur − gain·ref|` و `cd = فرق لون بعد التعويض`.
- **تصنيف الخلية** (`lo` = خلية شبه ملساء: الملمس < 4، أو < 3 في الوضع الدقيق):

  | النوع | الوضع العادي | الوضع الدقيق |
  |---|---|---|
  | `rem` (اختفى شيء) | `s<0.5 && tmax<0.55·tr && tmax<6 && tr−tmax>5 && !lo` | `(s<0.5 && tmax<0.7·tr && tr−tmax>3)` أو `(s<0.4 && cd>15 && tmax≤tr)`، وكلاهما مع `!lo` |
  | `add` (ظهر شيء) | معكوس `rem` (`tr<0.55·tmin` …) | معكوس |
  | `chg` (تغيّر) | غير lo: `(s<0.3 && textured && real) \|\| cd>24 \|\| md>35`؛ lo: `md>20 \|\| cd>15` | نفسه |

  - `textured = max(tr,tb)>8`.
  - `real` = فرق ملمس نسبي >30%، أو `cd>12`، أو `md>20`. هذا يمنع النصوص المطبوعة غير المحاذية من الإنذار.
  - `strong` = خلية rem أو add بفرق كبير (`<0.38`).
- **التجميع** (`group`):
  1. نوى strong أولاً، ثم rem/add منفردة، ثم chg.
  2. أقل حجم: rem/add خليتان، و chg 4 خلايا (3 في الدقيق).
  3. الدمج بفجوة خلية واحدة (2 في الدقيق).
  4. فلتر الشرائط الرفيعة.
- **منطقة chg** تتحول إلى rem أو add إذا مجموع الملمس قبل أكبر من بعد بوضوح (`>1.3×` وبفرق `>1.5` لكل خلية). هكذا تُكشف القطع الداكنة على سطح داكن.
- **`coarseSim`:** فحص بنيوي خشن لكل منطقة، ويُبقى فقط ما تشابهه < 0.85. هذا يقتل الإنذارات الكاذبة من الضبابية والتركيز.
- **المخرجات:** `{st, regions:[{type,cells,x,y,w,h,coarse}], changed, nx, ny, x0, y0, cs, W, H, shift}`، والإحداثيات نسبية (0..1).

**`motion(prev, cur, z, block=16, thr=14)`:**
- كتل 16 بكسل مع إزاحة ±2 ومتوسط معوَّض بالـ gain.
- عتبة نسبية.
- يرجع `[نسبة الكتل المتحركة، عددها]`.

**`rebase(base, F, z)`:** ينسخ منطقة العارضة **بالضبط** (بلا هامش) من الإطار الحالي إلى المرجع. الهامش كان يسبب «خطوط خياطة» كاذبة.

### 3.5 الأحداث (Events) وحالاتها

```
removal:  pending ──(رجعت)──► returned
             │ ──(بيع خلال saleWin)──► sold
             │ ──(انتهت المهلة grace، والتنظيف يمددها)──► incident ──► تنبيه
incident ──(رجعت)──► resolved/returned (تلقائي)
         ──(بيع متأخر خلال 24 ساعة)──► sold
         ──(المشرف)──► resolved: sold | justified | theft | false | returned
night:    خارج ساعات العمل (open/close + night=true) → incident فوراً
info:     added | swap | major | moved | pick | restock  (معلوماتي، بلا إنذار؛ pick/restock لرفوف البضاعة)
conceal:  incident «يحتاج مراجعة» (تجريبي) — بلا زر «تم بيعه»
removal ──(ظهرت القطعة نفسها في مكان آخر، ببصمتها)──► moved   (أو resolved/moved إذا كانت incident)
tamper:   zone='_cam'، sub = cover | turn → incident فوراً + تنبيه (أزرار المعالجة بلا «تم بيعه»)
```

- **شكل الحدث:** `{id, zone, kind, status, t_start, deadline, t_end, box{x,y,w,h}, img_b, img_a, img_c, img_p?, img_r?, who?, name?, note, sale?, resolution?, resolved_by?, t_resolved?, demo?}`.
- **البيع:** `addSale(zone, qty, ref, source)` يطابق أقدم الأحداث المعلّقة، والحوادث خلال 24 ساعة. و `trySale(e)` يطابق بيعاً مسجلاً قبل الشيل بـ `saleWin` دقيقة.
- **التنظيف:** `startCleaning(zone, minutes)` يمدد مهلة كل الأحداث المعلّقة إلى نهاية التنظيف + 60 ثانية.

### 3.6 الكاميرا وحركتها (أكثر شيء تعب عليه المشروع)

- **`startCamera(deviceId, facing)`:**
  - يتطلب HTTPS أو `file://` أو localhost.
  - بعد 3 ثوانٍ يحاول قفل التركيز عبر `applyConstraints({focusMode:'manual'})`. يعمل على Android فقط، والآيفون لا يدعمه.
- **لمس الشاشة:** `touchstart` في capture يضبط `S.touchAt`، ثم توقف 2.5 ثانية، ثم تثبيت، ثم إعادة معايرة تلقائية.
- **مستويات حركة الكاميرا:**

  | المستوى | السلوك |
  |---|---|
  | اهتزاز مستمر (`gm > 0.45`) | توقف كامل |
  | دفعة بسيطة | إعادة محاذاة هادئة |
  | ضربة واضحة (`gBase > 0.22`) | rebaseAll بعد قراءتين |
- **رسائل الحالة لكل عارضة:** «تراقب ✓»، «تنتظر: حركة / يد / شخص»، «الكاميرا تتحرك»، «تغيّر كبير… جارٍ التأكد»، «لمس الشاشة… انتظار»، «جارٍ التثبيت…».

### 3.7 طبقة الذكاء المحلي (MediaPipe) — اختيارية ومجانية

- **`ObjectDetector` efficientdet_lite0 (IMAGE):** يكشف الأشخاص، ويسمّي القطعة المشالة تقريبياً من فئات COCO (خريطة `OBJ_AR` للعربي: هاتف، لابتوب، ماوس…).
- **`GestureRecognizer`:** يكشف الأيدي (حتى 4).
- **يعمل عند الحاجة فقط:** في القراءة التي فيها حركة داخل عارضة، أو تغيّر يحتاج حكماً، أو شخص كان موجوداً. مرة واحدة لكل قراءة. ويُسخَّن عند التحميل لأن أول استدعاء يأخذ ثوانٍ. القراءة الهادئة صارت ~70ms بدل 1–2 ث على المعالج.
- **الفائدة:** تأجيل الحكم أثناء وجود يد أو شخص، ولقطة «من كان عند العارضة» قبل الشيل، وعدّ التفاعلات اليومية لكل عارضة.
- **بدون AI** يبقى النظام يعمل بالاعتماد على كشف الحركة فقط.

### 3.8 التخزين والتشغيل في الخلفية

- **IndexedDB** `haris_html`: `events` (حد أقصى 3000) و `sales`.
- **localStorage:**
  - `haris_cfg`: الإعدادات.
  - `haris_zones`: العارضات.
  - `haris_cleaning`: نهاية التنظيف لكل عارضة.
  - `haris_inter`: التفاعلات، آخر 60 يوماً.
  - `haris_who`: اسم المشرف.
- **Worker-blob ticker** كل 500 ms حتى لا يبطئ المتصفح المؤقتات في الخلفية، و **wakeLock** لمنع إطفاء الشاشة.
- **التنبيهات:** Notification API، وصوت، و **Telegram** (`fetch` بـ `mode:'no-cors'` و FormData مع صورة).

## 3.11) الحكم الذكي عند كل حدث (Claude) — بموافقة المستخدم

- **السبب:** «لا زال غبي وبدائي». المحرك قواعد على البكسلات لا يفهم المشهد، وكل إصلاح رقعة لحالة واحدة.
- **التصميم:**
  - المحرك على الجهاز يبقى المنبّه المجاني على مدار الساعة.
  - **عند كل حدث فقط** (removal، night، moved، added، swap، major، conceal) تُرسل حتى 4 صور صغيرة: مقارنة، وقبل، ولحظة اليد، وبعد/الوجهة.
  - تذهب إلى دالة الخادم `judgeEvent` في `functions/judge.js`. تستدعي Claude Opus 5.5 افتراضياً (Haiku 5.5 اختياري)، بمخرجات JSON مقيّدة بمخطط، وبـ `fallbacks: "default"` لـ Opus.
  - يرجع `{verdict, item, summary, confidence, risk}`، و verdict إحدى القيم: taken، moved، returned، added، rearranged، concealed، no_change، unclear.
- **تطبيق الحكم** (`JUDGE.apply` في الصفحة):
  - ثقة ≥ 0.7 وحكم «ليس أخذاً» على حالة معلّقة (أو اشتباه إخفاء) ← تُغلق (`moved` / `returned` / `resolved:false`) بسبب مكتوب.
  - ثقة ≥ 0.7 وحكم «أخذ أو إخفاء» على حدث معلوماتي (moved، added، swap، major) ← يتحوّل إلى `removal` معلّق بمهلة، أو `night` ليلاً.
  - غير ذلك ← يُعرض الحكم فقط، ويبقى قرار المحرك.
  - المهلة تنتظر الحكم حتى 45 ثانية إضافية (`aiPending`).
- **الأمان:**
  - مفتاح Anthropic على الخادم فقط.
  - الجهاز يرسل `x-guard-key` (رمز الربط).
  - حد يومي على الجهاز (`judgeMax`) وعلى الخادم (`GUARD_DAILY`)، وحدود لعدد الصور وحجمها.
- **الاستضافة:** النشر ينسخ `haris.html` إلى `https://<project>.web.app/haris.html`، ويعيد توجيه `/api/judge` إلى الدالة، فالرابط الافتراضي يعمل تلقائياً من نفس الموقع.
- **بلا إنترنت أو بلا إعداد:** يعمل الحارس كما كان.
- **تأكيد الرجوع (الجلسة 7):** قبل إغلاق حالة نُبّه عليها «رجعت»، `JUDGE.confirmReturn` يرسل مقارنة مقرّبة (نصف «قبل» من `img_c` بجانب `zoom()` للمكان الآن) + الصورتين الكاملتين. «taken/concealed» بثقة ≥ 0.6 ← تبقى مفتوحة؛ غير ذلك أو تعذّر الاتصال ← تُغلق كما قرر المحرك. جُرّب على Haiku الحقيقي بحالة الكرة الزرقاء: بالصورة الكاملة فقط «no_change 0.6» (لا يرى القطعة الصغيرة)، وبالمقرّبة «taken 0.8/0.7»؛ والرجوع الحقيقي «no_change» ← تُغلق.
- **الاختبارات:**
  - `tests/judge_server.js`: عميل Claude وهمي.
  - `tests/judge_client.js`: خادم وهمي عبر Playwright.
  - **لم يُجرَّب على Claude الحقيقي داخل بيئة التطوير** (لا مفتاح). أول تجربة حقيقية بعد ضبط الأسرار والنشر.

## 8) القيود المعروفة (كن صريحاً بها مع المستخدم)

1. **الكاميرا يجب أن تكون ثابتة على حامل.** الأجسام القريبة جداً تسبب إعادة تركيز. قفل التركيز يعمل على Android فقط.
2. **الموبايل يحتاج HTTPS** للكاميرا. الـ artifact sandbox يمنع الكاميرا، فالملف يُفتح محلياً أو يُستضاف (GitHub Pages أو Netlify أو Cloudflare Pages).
3. **البيانات محلية لكل متصفح.** لا يوجد خادم مركزي ولا مزامنة بين الأجهزة أو الفروع.
4. **تسمية MediaPipe عامة** (فئات COCO). لا يعرف موديل الهاتف.
5. **بدون AI:** ذراع ثابتة طويلاً قد تفتح حالة «معلّقة» تُغلق عند الرجوع، لكنها لا تُنذر إلا بعد المهلة.
6. **رفوف البضاعة (`stock`):** تحتاج كاميرا مائلة من الأعلى ترى مقدمة الصفوف. القطعة المأخوذة من الخلف أو من صف تبقى واجهته مكانها (رف بدافع زنبركي) لا تُرى. الالتقاط ≠ سرقة: هو عدّ يُقارن بالمبيعات.
6أ. **كشف الإخفاء تجريبي، ولم يُجرَّب على فيديو حقيقي بعد:** الاختبارات بعلامات ملونة بدل جسم حقيقي. يد ترتاح بجانب الجسم بعد لمس الرف، أو إخراج الموبايل، قد ينبّه. يحتاج كاميرا ترى جسم الزبون (من زاوية الممر لا من أمام الرف). يجب ضبطه بمقاطع حقيقية من المحلات قبل الاعتماد عليه، مع سياسة خصوصية (يراقب حركة الأشخاص).
6ب. **قطعتان متطابقتان تماماً** (نفس الموديل واللون): إذا سُرقت واحدة ونُقلت الأخرى في نفس اللحظة، قد تُطابق الخطأ. المطابقة واحد لواحد، فتبقى حالة واحدة على الأقل.
6ج. **العارضات المتداخلة** قد تنسب التغيّر للعارضة الخطأ.
7. **قطعة على سطح بنفس لونها وملمسها تماماً** صعبة الكشف بأي محرك بصري.
8. **نسخة Python متأخرة** عن تحسينات JS.
9. **أحداث معلوماتية زائدة:** تغيّر التعريض التدريجي قد يولّد أحياناً أحداث `swap/added`. هي بلا إنذار، لكنها ضجيج في السجل يمكن تقليله لاحقاً.
10. **المتصفح قد يوقف الكاميرا** عند قفل الشاشة أو التبديل لتطبيق آخر. يوجد wakeLock، لكن الأفضل جهاز مخصص بالشحن.

**تجربة: نموذج إخفاء من بيانات عامة (2026-11-28).** درّبنا مصنِّفاً على نقاط الجسم من PoseLift (WACV 2025: 41 فيديو سرقة حقيقية + 104 تسوّق عادي، كاميرات سقف، COCO-17)، بنافذة ~2.4 ث وبإيقاع CONCEAL (2.5 قراءة/ث)، وتقييم بفيديوهات لم يرها (GroupKFold). النتيجة: AUC ≈ 0.67–0.72 (مثل أفضل نماذج الورقة 0.61–0.67)، وعند ≤ 10 إنذارات كاذبة/ساعة يلتقط ~2 من 36 سرقة فقط. **الخلاصة: الوضعية وحدها من بيانات عامة قليلة لا تصلح كاشفاً مستقلاً**؛ لم يُدمج. الطريق: قاعدة «لمس العارضة ← الجسم» (CONCEAL) كمُطلِق، ثم Claude يحكم على صور اللحظة، ثم أمثلتنا المعلّمة. ملاحظة ترخيص: بيانات PoseLift تتطلب إذناً للاستخدام التجاري (invent@charlotte.edu).

**نموذج حركة الإخفاء (2026-11-28) — مُدمج.** مدرَّب على MNNIT Shoplifting Dataset 2022 (182 مقطعاً: 92 سرقة / 90 عادي؛ **CC BY 4.0**، المصدر: data.mendeley.com/datasets/r3yjf35hzr — يجب ذكر المصدر). نقاط MediaPipe Pose Lite (نموذج الصفحة نفسه) بإيقاع 2.5/ث، نافذة 6 قراءات، 41 ميزة (`DET.poseNorm` / `DET.poseWindowFeats`)، أشجار HistGradientBoosting (120×عمق 3، `src/models/conceal_model.json`، تُضمَّن عند البناء، `DET.treeProb`). على مقاطع لم يرها: AUC 0.84 (عند 0.95: 36/92 سرقة مقابل 5/90 عادي). الاستخدام: احتماله يُرفق بكل تنبيه إخفاء (`e.cp`)، ويطلق تنبيهاً بنفسه فقط إذا لمست اليد عارضة خلال 8 ث ثم ≥ 0.95. اختبار مطابقة JS/Python في `tests/unit_detector.js`.

**كاميرات السقف (RetailAction، ICCV 2025، Standard AI Dataset License — مجاني حتى إيرادات 10,000$ ثم يلزم ترخيص).** محرك مِرصاد (`compareZone` بالوضع الدقيق) على 1,277 عينة حقيقية من السقف: يكشف ~82–89% من «الأخذ» عندما لا يغطي أحد المكان. أغلب «التغيّرات» في الأماكن الضابطة أجزاء أشخاص لم يكشفها EfficientDet من الأعلى (ضعفه من زاوية السقف — مهم لهيكفشن). فلتر مناطق (`DET.regionFeats`، 16 ميزة) يخفّض الأماكن الضابطة المنبَّهة ~35% مع الحفاظ على 95% من الأخذ المكتشف؛ احتماله يُسجَّل في `dbg.ra` (`src/models/ra_filter.json` إن وُجد).

## 9) خارطة الطريق المقترحة (بالأولوية)

1. **استضافة HTTPS** + PWA (manifest + service worker) لتعمل كتطبيق على الموبايل وبدون إنترنت، بعد تخزين نماذج MediaPipe محلياً.
2. **خادم مركزي خفيف:** Supabase أو Firebase، أو Node و SQLite. الهدف:
   - كل جهاز يرفع الأحداث وصورها المصغرة.
   - لوحة إدارة لكل الفروع.
   - مزامنة الإعدادات والعارضات.
   - صلاحيات (موظف، مشرف، مدير).
3. **ربط نقطة البيع (POS):** إذا كان للعارضة ربط بقسم أو SKU، يُسجَّل البيع تلقائياً، فتنخفض «الحوادث» كثيراً.
4. **دمج النظامين:** نفس العارضات ونفس الموظفين. وقت التنظيف في تطبيق النظافة يفتح «نافذة تنظيف» تلقائياً في الحارس.
5. **حساسية لكل عارضة** (عادي أو دقيق لكل zone بدل إعداد عام)، ومهلة لكل قسم.
6. **إعادة الربط مع Hikvision** لاحقاً: إما تحويل `detector.js` لعامل Node يسحب لقطات ISAPI، أو نقل التحسينات إلى `detector.py`، مع استخدام `mock_nvr.py` للاختبار.
7. **إشعار خصوصية للموظفين** (كاميرا تراقب العارضة لا الأشخاص)، وسياسة احتفاظ بالصور.

## 10) ثوابت لا تُكسر

- **ممنوع إدخال المنتجات يدوياً.** النظام يعمل على «التغيّر» لا «الهوية».
- **ممنوع استدعاء AI سحابي لكل إطار** (تكلفة). المسموح فقط استدعاء نادر اختياري عند حادثة، إن طُلب لاحقاً.
- **الشيل لا يُنذر فوراً** (إلا ليلاً): مهلة، ثم رجوع، أو بيع، أو تنظيف، ثم إنذار.
- **لا تُعِد ضبط المرجع كاملاً بسبب تغيّر الإضاءة أو التعريض وحده.** فقط عند إزاحة حقيقية مستقرة وبلا أشخاص.
- **الواجهة عربية RTL ورسمية**، تعمل على موبايل بعرض 390 بكسل، وملف واحد بلا build tools (عدا حقن `detector.js`).
- **أي إصلاح لمشكلة ميدانية جديدة:** أعد إنتاجها بفيديو في `make_videos.py`، وأضف سيناريو في `run_scenarios.py`، ثم أصلح.
